# Измерения 0.3.0-rc.6

## Что ускорено

При проверке и сборке adopt программа читает и проверяет XML целиком,
но не строит дерево, если нужны только корневой тег и атрибут версии.
Использован встроенный Expat; новое внешнее ПО не требуется. Доступ к атрибуту
совпадает с ElementTree. Проверки всех байтов, SHA, состава, типов файлов,
метаданных и происхождения из CF сохранены. Rust и сериализация не менялись.
XML/BSL не берутся из контрольных выгрузок. Публичные параметры и defaults прежние.

## Текущий финальный код: реальный PostgreSQL → две XML

Одинаковый Документооборот, параметры и CF. Прочитана СУБД в read-only транзакции,
собраны две CF, сформированы и полностью проверены две XML-выгрузки.
Режим fast/adopt/stream/bind-copy; обе стороны и итоговая проверка последовательны,
восемь потоков readback. Контроль — опубликованная rc.5, затем финальная rc.6.

## Предыдущая итерация: только потоковая проверка

До расширения сборки выполнены четыре live PostgreSQL прогона с verify-overlap
и финальной проверкой 2+6: старая 3:47–3:57, промежуточная новая 3:40–3:43.
Все 46 786 файлов / 11 774 BSL совпали. Медиана полного времени меньше на 4.43%,
финальная проверка — примерно на 6%. Часть разницы объясняется прогревом чтения
СУБД. Эти четыре запуска нельзя считать прогонами финального кода сборки.

Отдельная повторная проверка уже готового ERP, без создания новой XML:
старый парсер 315.60/313.36 с, потоковый 224.05/297.47 с. Медиана меньше на
17.08%, процессорное время — на 13.47%. Все 277 048 файлов / 58 049 BSL /
20 858 073 231 байт совпали. Эта проверка пригодна для текущего readback:
его код и горячий код парсера сохранены точно, добавлен только атрибутный
accessor для сборки. Это ускорение проверки, а не всего DB→XML процесса.

Общий пул потоков после основной оптимизации дал менее 1% над лучшим
последовательным запуском; пакетирование мелких заданий — около 1% с
перекрывающимся разбросом. Оба варианта в продукт не включены.

## Что произошло с большим ERP-прогоном

Контрольная версия от сохранённых настоящих MSSQL CF до двух XML:
36:28.8, все 277 048 файлов / 58 049 BSL exact.
Промежуточная версия с новым readback: FAILED_PRODUCT_SAVED_CF_REPLAY,
измерено 3018.04 с, предел 3000 с.
Этот прогон не является чистым сравнением скорости: загрузка хоста измерена
около 85% CPU, замедлились и неизменённые Rust-конвертер и перенос файлов.
После фиксации смешанного контекста параллельно выполнялись небольшие проверки
следующей итерации; это также отмечено в исследовательском отчёте.

Финальная версия с потоковой сборкой НЕ проходила новый полный ERP-экспорт в
этом окне. Поэтому новое полное время ERP для неё не заявляется. Неудачный или
частичный прогон не считается готовой XML. Новое чтение MSSQL не измерялось.
Подтверждение актуального end-to-end ускорения — текущая пара PostgreSQL выше;
прежняя большая проверка обосновывает повторное использование парсера.

## Проверки и ограничения

Windows: 138 методов без ошибок, два symlink subcase SKIP. Linux offline:
254 метода, 233 PASS, 21 SKIP (17 с запрещёнными memory-limit, четыре Windows).
Тесты покрывают namespaces, DTD/entities, кодировки, большие токены, поздние
ошибки, корневые атрибуты и совпадение с ElementTree. Небольшой полный прогон
двух сохранённых CF: 73.83 с, все 15 файлов / 1 BSL exact.
Первый tiny был отклонён CPU-preflight до конвертации; принят обычный
последовательный режим с меньшей потребностью в CPU. Защиты не отключались.

Проверки выполнены руководителем этапа; независимого ревьюера в этом окне не было.
Новая обратная загрузка в платформу 1С не проводилась. Известные ограничения
сериализации, opaque и закрытые исходники сохранены. Для Документооборота
отмечены 6 opaque записей основной и 5 поставщика; их полная семантика не
заявляется, исходные CF сохраняются. COMPLETE_WITH_LIMITATIONS остаётся честным
итогом. Архивирование и offline install не считаются новым XML-экспортом.
Исторические проверки в release-validation.json явно помечены NOT_RERUN.
Документация парсера: https://docs.python.org/3/library/pyexpat.html
